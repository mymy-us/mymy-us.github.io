    How do you calculate MODAPTS for a process that does not exist?

    By Tim Y |Posted on Jul 12, 2026 | 6 min read

    Topic: Estimating manual work before the workstation exists
    The academic view: An exam question describes every motion. You select the MODAPTS codes and calculate the time.
    The workplace reality: Your manager wants to know whether a proposed process can meet the required pace. The workstation has not been built. You must first work out what the operator would actually do.

    At school, somebody has already decided which hand reaches, how far it moves, and where the part goes. At work, those decisions may all belong to you.

    MODAPTS is a predetermined time system for analyzing manual work. Once you define the method, you can assign times to its motions. But the code table cannot tell you where to put the carton or what the operator’s other hand is doing.

    You have to describe those motions first. That is difficult when the workstation exists only in your head: you might imagine the carton close by in one step and farther away in the next. You need a layout to refer to while working through the sequence.

    How do I make the imagined work concrete?

    Start with what the operator must complete and roughly how fast. Use a rough 2D or 3D layout, cardboard, or tape to place the operator, material, tools, and fixture at approximate distances and heights.

    Alongside the layout, write a motion storyboard: short descriptions of what happens through one complete cycle. Work back and forth between them. Moving the carton changes the reach; an awkward handoff in the storyboard may give you a reason to move the carton.

    Use this bottle-loading sequence as an illustration:

    Locate a bottle in the carton → grasp it with the left hand → pass it to the right hand → insert it into a moving fixture → prepare for the next bottle.

    Keep this as one continuous story. If the left hand returns while the right hand inserts, describe both actions in that step. Include any walking and looking where they happen in the same cycle.

    This describes the bottle’s path, but it leaves part of the work unclear. During insertion, you know what the right hand does. You have not said where the left hand goes after the handoff, or which way the operator is looking.

    What is the rest of the operator doing?

    The left hand might return to the carton while the eyes follow the fixture. The torso might turn even though both feet stay planted. You need these details to work out what happens next.

    At each storyboard step, check six channels: right hand, left hand, right leg, left leg, torso, and head. Under the head channel, include vision and cognition: what the operator must notice, decide, or confirm.

    Ask where each channel starts, what it does during the step, and where it finishes. For the insertion step, one proposed arrangement could look like this:

    ChannelDuring insertionEnd state
    Right hand / armGuides and releases the bottleEmpty hand near the fixture
    Left hand / armReturns toward the cartonResting on or near the carton
    Right leg / footMaintains stanceSame position
    Left leg / footMaintains stanceSame position
    TorsoFaces the loading positionStill oriented toward the fixture
    Head, vision, and cognitionTracks the fixture, judges alignment, confirms insertionAttention still on the fixture

    The six rows help you check what happens during the same step. Adding six separate time totals would count overlapping work more than once.

    Describe objects and equipment through their effect on the person: the right hand holds the bottle, or the operator waits for the fixture. That is enough for this human motion check.

    In the last column, the left hand finishes near the carton. The next storyboard step still says “prepare for the next bottle,” though part of that preparation has already happened.

    Why does the ending position matter so much?

    The next step starts where the previous one ended. If the left hand is already near the carton, sending it all the way back again under “reset” counts the return twice. But you still have to locate and grasp the next bottle, and the eyes may still be checking insertion.

    Carry each ending state into the next step. Replace “reset and repeat” with whatever reaching, looking, releasing, or repositioning remains.

    Finally, connect the end of the cycle to the beginning of the next one. An imaginary operator should not teleport back to a convenient starting position.

    The duplicate return is gone, but the table still contains an assumption: the left hand returns while the right hand inserts. You need to check whether the operator can do both together.

    Can all those movements happen together?

    The operator may be able to return an empty hand toward a familiar carton position while watching insertion. Selecting the next bottle could require looking into the carton, so that part may have to wait. The hand is free, but the operator’s attention is still on the fixture.

    Use the head channel to check this. If judging alignment takes heavy concentration, the other motion might slow down or start later, leaving only part of the movements overlapping. Mark the portion you are unsure about. Assuming everything happens separately can be just as misleading as assuming perfect overlap.

    Compare a case with plausible overlap against one where the second action starts later. Use a mock-up or a comparable operation to help judge which is realistic. Label unverified timing adjustments as engineering assumptions. There is no basis here for adding the same “thinking penalty” to every task.

    With the positions and overlap worked out, you have the motion description your exam paper used to give you. You can start assigning codes, keeping the uncertain parts marked.

    When do I assign the MODAPTS codes?

    You can now translate that description using the MODAPTS coding and simultaneous-activity rules you were trained to use. Check each code against the layout and storyboard: which movement, handling condition, or position supports it? A missing detail sends you back to clarify that part of the method.

    The manual work time alone does not tell you the station’s cycle time. You also need the machine’s timing, even if you have already written “wait for fixture” in the human storyboard. Work out how the two fit together before comparing the station with takt, the pace required by demand.

    When you present the estimate, state which arrangement and method it assumes. Calculate alternative cases for uncertain reaches, corrections, or overlap so management can see how those assumptions affect the time.

    Compare those cases with the required pace. If even the favorable case is too slow, you need to change the arrangement. Return to the movements that take the time.

    What if the proposed method cannot meet the target?

    Return to the bottle’s handoff and insertion. Could repositioning the carton remove the handoff? Could a guide reduce the alignment demand? Would a feeding device remove enough manual work to justify developing it?

    For each option, revise the layout and motion sequence together, then recalculate the affected work. Count any loading, checking, or waiting the device would add. Specify what the machine would do before claiming the saving.

    You can then show management how far the proposed method misses the target and what changes could close the gap, before anyone buys equipment.

    Keep the layout and storyboard with the calculation so you can explain the movements behind each code, including their starting positions, overlap, and how they connect to the next step. When the workstation becomes available, go through the sequence with operators and compare the estimate with actual work. Start with the motions and overlap you marked uncertain.
